# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / line 72 | Readiness probe returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | Stopping or disconnecting MongoDB still returned HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` inside a try-except block, raising `HTTPException(503)` if ping fails. |
| 2 | `create_employee()` / line 79 | "Check-then-insert" race condition on `emp_code`. Concurrent requests with the same code could both pass `find_one`. | Two concurrent `POST /employees` requests with identical `emp_code` created duplicates or threw unhandled errors. | Added a unique index on `emp_code` at startup and caught `DuplicateKeyError`, converting it to HTTP 409. |
| 3 | `EmployeeIn` / lines 53-61 | Missing validation that `shift_start` differs from `shift_end`. | Sending equal shift start and end (e.g., `"09:30"`, `"09:30"`) returned 201 instead of 422. | Added validation in `create_employee` requiring `shift_start != shift_end`, returning HTTP 422 if equal. |
| 4 | `create_employee()` / line 82 | `created_at` returned as Python datetime / string instead of integer epoch milliseconds. | Response `created_at` failed OpenAPI validation schema `EpochMillis` (`int64`). | Stored UTC BSON datetime in MongoDB and converted to integer epoch milliseconds in the API response. |
| 5 | `list_employees()` / line 93 | Off-by-one pagination bug: `skip = page * page_size` skipped the entire first page (`skip = 20` for `page = 1`). | Calling `GET /employees?page=1&page_size=20` returned 0 items even when 5 employees existed in DB. | Fixed calculation to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` / line 94 | `total` count ignored the department query filter. Ran `db.employees.count_documents({})` on the whole collection. | Querying `GET /employees?department=Sales` returned 2 items but `total: 6`. | Changed to `db.employees.count_documents(q)` to count only filtered documents per R10. |
| 7 | `list_employees()` / line 95 | Undefined sorting order. Query did not specify a `.sort()`. | Employee list returned in arbitrary MongoDB natural insertion order instead of `emp_code` ascending. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 8 | `compute_late_minutes()` / line 37 | Grace period boundary defect: `minutes if minutes > 10 else 0` where `minutes = int(seconds / 60)`. | A punch-in at 09:40:01 (10 min 1 sec after 09:30) yielded `minutes = 10`. `10 > 10` evaluated to False, returning 0 instead of 10 per R2. | Checked elapsed seconds directly: `if elapsed_seconds > 600: return int(elapsed_seconds // 60)` else `0`. |
| 9 | `compute_late_minutes()` / lines 34-36 | Timezone offset error: replaced hour/minute directly on UTC datetime using IST shift times. | Punching in at 03:58 UTC (09:28 IST) was treated as 03:58 against a 09:30 shift, resulting in negative elapsed times or 5.5h offsets. | Converted UTC instant to Asia/Kolkata timezone (`IST`) before calculating shift boundary difference. |
| 10 | `compute_work_hours()` / line 41 | Python `round()` uses round-half-to-even (banker's rounding) instead of round half-up. | Duration yielding `2.675` hours rounded to `2.67` instead of `2.68` required by R4. | Replaced with `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 11 | `compute_overtime()` / line 47 | Missing 30-minute minimum overtime threshold. Starter returned `max(0, int(...))` for any minute > 0. | Working 5 minutes past shift end returned `overtime_minutes: 5` instead of `0` (Sample 1 in `DATA_MODEL.md`). | Added threshold check `if ot_seconds >= 1800: return int(ot_seconds // 60)` else `0` per R3. |
| 12 | `compute_overtime()` / line 46 | Overnight shift date handling was incorrect for `shift_end <= shift_start`. | For 22:00 - 06:00 shift on 2026-07-06, shift end was set to 2026-07-06 06:00 IST (16h before shift start) instead of 2026-07-07 06:00. | Calculated shift end on `date + 1 day` when `shift_end <= shift_start`. |
| 13 | `punch_in()` / line 101 | Missing employee existence check caused unhandled `TypeError` (HTTP 500). | Punch-in for non-existent employee caused `emp["shift_start"]` to fail with `TypeError: 'NoneType' object is not subscriptable`. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 14 | `punch_in()` / line 104 | "Check-then-insert" race condition on `(emp_code, date)`. | Two simultaneous punch-in requests for the same date both passed `find_one` and created duplicate logs. | Created compound unique index on `("emp_code", 1), ("date", 1)` and handled `DuplicateKeyError` returning HTTP 409. |
| 15 | `punch_in()` / lines 102-103 | Attendance date assignment ignored overnight shift rules (R1) and machine timezone. | Punching in at 01:10 IST on an overnight shift was assigned the current calendar day instead of the shift's starting day. | Converted instant to IST and checked `punch_in_ist.strftime("%H:%M") < shift_end` to assign previous day for overnight shifts. |
| 16 | `punch_in()` / line 119 | Unwanted internal `id` returned in response body. | Response contained `"id": "60c..."`, violating `AttendanceRecord` schema and problem statement rules. | Removed internal `id` / `_id` fields, returning exact schema per API contract. |
| 17 | `list_attendance()` / lines 144-147 | Loaded entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorted in Python. | High memory usage and latency on large collections (~100k documents). | Applied sorting `[("date", -1), ("emp_code", 1)]`, `skip()`, and `limit()` directly in MongoDB. |
| 18 | `list_attendance()` / line 136-141 | Missing date range validation when `date_from > date_to`. | Passing `date_from=2026-07-10&date_to=2026-07-05` executed an impossible query returning empty list instead of HTTP 422. | Added validation `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 19 | Application Startup / lines 22-25 | No database indexes created on startup. | All queries and lookups ran as `COLLSCAN`, failing performance and explain requirements. | Created all required indexes idempotently inside FastAPI `lifespan` startup handler. |

## Examined and Decided Not a Defect

1. **PyMongo Connection Pooling**: The starter initialized `MongoClient` at module level without explicit `maxPoolSize`. PyMongo's default pool size of 100 connections is well-suited for high concurrent loads with FastAPI.
2. **Storing Computed Values**: Storing derived fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`) directly in MongoDB was retained. As specified in `DATA_MODEL.md`, stored derived values are authoritative and must be read by analytics rather than recomputed on the fly.
